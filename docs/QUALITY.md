# UI / UX 质量标准

按任务风险选择检查，不因换一个颜色重跑所有业务测试。共享组件变化会影响多个项目，应测相应交互和代表页面；数据/身份/备份变化另外验证兼容性。

## 视觉与布局

- 浅色、深色与跟随系统；主题切换后状态栏/手势栏图标仍可读。
- 320 逻辑像素窄屏、常规手机和宽屏；200% 字号下可滚动、文字自然换行，无重叠或关键截断。
- 默认、按下、禁用、加载、空、失败、成功、超长内容；有图/无图都成立。
- 主次信息清楚，危险色只用于明确后果；不为凑网格高度压缩用户内容。

## 交互

- 一条主要路径能从头到尾完成，取消/返回能回到合理位置。
- 快速连点、中途切换、失败重试不会重复写入或丢失草稿。
- 键盘弹起后当前输入和提交可到达；系统返回、点击返回、关闭弹层走一致规则。
- 搜索/筛选/详情往返保留上下文，长列表使用稳定 ID 和虚拟化。
- 页面没有未接线的主要按钮；若展示的是合成流程，必须明确标注。

## 无障碍

- 可交互区域至少 48 逻辑像素；小图标置于足够大的点击容器内。
- 按钮、字段、开关、分段选择都有标签和正确语义；开关只出现一次，不重复读两个控件。
- 一般正文至少 4.5:1，关键控件边界至少 3:1；颜色之外也传达状态。
- TalkBack / 键盘按合理顺序到达，弹层进入/退出时焦点正确；提示不会无休止重复播报。
- 减少动态效果时没有持续脉冲或大幅位移；动效运行与帧率需实际检查。

## 数据与安卓平台

共享 UI 不触碰应用 ID、原签名、正式数据库或用户文件。引入库不自动改变 minSdk/targetSdk 或依赖大版本。需要迁移时明确备份与失败保持旧数据。

真机上检查手势返回、预测性返回、IME、安全区、文件/媒体选择、权限拒绝、生命周期和大文件。宿主截图与 renderer test 不等于这些场景已通过。

## 证据写法

记录命令、工具版本、来源提交/工作树状态、passed/failed/not run 与未覆盖内容。截图只证明对应状态的可见布局，不证明动画、真实保存或发布。一次相关验证通过后，只有新修改、失败或剩余风险才扩大/重复检查。

参考：[Android 无障碍](https://developer.android.com/guide/topics/ui/accessibility)、[Compose 默认语义](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。

# 可复用 UX 模式

这些是跨框架的行为约定；组件实现部分规则，数据持久化、路由与系统集成由项目实现。不能把文档视为已有后端能力。每次接入选当前相关模式即可，不给所有页面强加整套流程。

## 01 · 编辑与保存

进入时读取已保存内容，编辑只改变草稿。状态为 clean → dirty → saving → clean / error。只有持久化成功才标记已保存；失败保留输入、位置和附件引用，可重试。saving 阻止重复提交，不把按钮隐藏得失去上下文。新分享/外部输入不能静默替换正在编辑的草稿。

返回按钮、系统返回、路由跳转、下滑关闭都应共用离开保护。dirty 时提供“继续编辑 / 放弃修改”，默认不丢内容；saving 时避免中途丢弃。进程死亡恢复由项目草稿存储负责，当前三个编辑模板本身不提供磁盘持久化。RN 导航器的 beforeRemove 等额外离开路径须由宿主接入。

验收：输入 → 模拟失败 → 原文仍在 → 重试成功；dirty 返回取消 → 仍在原位置；确认放弃 → 已保存版本未被草稿污染。

## 02 · 搜索与筛选

搜索字段有名称，非空时可清除。区分“库为空”和“没有搜索结果”，后者显示当前条件并提供清除筛选。返回详情后保留关键词、筛选和列表位置。大列表用稳定 ID；不要依赖列表索引作为条目身份。

查询在本地还是远程、是否有 debounce、是否取消旧请求由数据层决定；旧请求不能覆盖新关键词的结果。错误时保留已有列表。

## 03 · 导入与恢复

选择来源 → 解析/校验 → 展示范围、条目数、警告、冲突策略 → 用户确认 → 写入 → 反馈。预览前不修改正式库；取消不写入。恢复不等于覆盖，需由产品明确合并/复制/替换，并在替换前保留可恢复备份。

文件大小、解压总量、格式、重复条目和附件可用性由导入器验证；这里仅提供预览 UI。失败说明当前完成了哪一步，不以“全部成功”掩盖部分失败。验收包含取消、损坏文件、重复数据、失败保持旧库。

## 04 · 列表与详情

列表只保留决定打开哪条内容所需信息。整行点击有明确去向，右侧箭头不是唯一提示。详情与编辑分开，查看不会自动写入。返回保留列表滚动位置与筛选。

列表为空给一个自然的起点；首次加载没有内容可以用骨架，刷新保留旧内容并说明失败。长列表采用各平台虚拟化列表，不把大数据库一次放进 Column / ScrollView。

## 05 · 设置

按用户心智分组：显示、阅读、资料、隐私、关于。高频项直接显示，危险和低频项放在靠后位置。只有真实可配置的能力才出现开关；需要先连接/授权的操作解释依赖，不伪装成已经打开。

即时开关在失败时恢复原值并给反馈；需保存的多字段编辑明确提交。主题默认可跟随系统，显式浅/深色选择优先并由宿主保存。

## 06 · 阅读与局部编辑

正文排版优先于面板。可调整字号/行距/主题，保留阅读位置；选择文本后再显示相关操作。阅读界面保持挂载，关闭编辑回到原段。局部替换需要稳定书籍/章节 ID、选区和版本校验，不能把修改写到相似但错误的片段。

阅读组件只负责排版，不承担 EPUB/PDF 解析、书签、分页或版本一致性。成熟引擎见 [选型](STACK_CHOICES.md)。

## 07 · 删除、归档、撤销

归档可恢复，与永久删除区分。可撤销操作优先就地反馈 + 撤销；不可逆删除说明对象和后果，用具体动词“删除这条记录”。撤销必须核对版本，不能覆盖操作后发生的其他编辑。

不可逆操作不得只靠红色或滑动手势；提供可见入口和确认。确认对话框不使用模糊的“确定”。

## 08 · 加载、离线和重试

区分初次加载、保留旧内容的刷新、明确进度、未知进度和已失败。仅当进度真实可测才显示百分比。重试重新发起当前意图，不重放已成功的写操作。取消或页面离开后，旧响应不再更新新页面。

离线时可读的本地内容继续可读，提示需要网络的部分。耗时任务需超时、失败/取消与恢复路径，不能永远 loading。

## 09 · 表单与校验

字段有持续可见的标签，placeholder 不能充当唯一名称。必填只限真正需要的字段；适时展示错误，并说明如何修正。错误与对应输入关联，保留用户原始输入，不在每次键入时过度格式化。

键盘类型匹配输入；金额的精度、负数、空值和地区格式由业务处理。最后一个字段/提交按钮应能在键盘弹起时滚动可见。不要默认先索取所有权限。

## 10 · 导航与弹层

底部导航用于稳定的顶级目的地，二级内容走页面返回。需要长时间输入、多步骤或复杂比较时优先完整页；短选择用底部面板。层级不超过用户能理解的范围，不连续堆叠三层 Sheet。

Android 返回先关闭键盘/当前临时层，再回上一层。弹层有可见关闭方式、焦点进入与归还；重要编辑必须覆盖拖动关闭和系统返回路径。导航器、窗口与 IME 行为须真机检查。

## 11 · 媒体与权限

优先系统选择器和最小权限。预览原媒体，导入时明确是否复制到私有库；缩略图不等于原件。视频默认静音且不在后台继续播放，离开停止；录音仅在用户启动后开启，说明暂停、完成和强杀边界。

解码、缓存、播放器和文件访问采用成熟库。共享组件不申请权限、不打开摄像头、不下载用户文件。

## 12 · 备份与更新

备份说明包含内容与敏感性、位置和完成状态；恢复前先验证格式与完整性。应用更新区分已有版本、检查中、无更新、发现新版、下载中、校验、系统安装与失败。网络与登录只在真实需要时启动。

共用 UI 不更改原签名、包名、升级白名单或数据格式；现有 [android-update-kit](https://github.com/h516df/android-update-kit) 是集成候选，接入前检查具体项目，不在本库重写更新器。

## 13 · 首次使用

先让用户完成最小有用动作，再逐步补资料；可选项允许跳过。空白应用不塞入未标注的假数据。展示 App 的合成样例不可作为业务项目正式初始数据。

## 14 · 反馈与文案

说发生了什么、影响什么、下一步做什么。“保存失败，输入已保留，请重试”比“错误 500”有用；技术细节放可展开诊断。成功状态使用事实，不以演示数据冒充真实统计。

触感只在明确的选择或完成点轻触一次，尊重系统设置。短反馈可用 Snackbar / status；阻塞错误应留在页面，不能一闪而过。

## 15 · AI 候选与人工采用

仅在产品确实有 AI 功能时采用：配置状态 → 预览发送范围 → 明确发送 → 加载/失败可重试 → 比较候选 → 用户采用/取消。取消不修改原文，采用前校验原版本仍一致。不得静默发送全文或把生成中当作已保存。

本库没有供应商调用、模型接入或密钥管理实现，仅给交互模式；消费项目需独立配置和验证。
